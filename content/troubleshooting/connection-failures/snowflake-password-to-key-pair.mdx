---
title: Switch from a password to a key pair
description: Replace your Snowflake password with a key pair to keep your tools and dashboards connected.
---

<Term>Snowflake</Term> is ending password-based connections for tools and dashboards. DataHawk supports key-pair authentication for these connections.

A **password** is a secret you enter to connect. A **key pair** has two matching parts. DataHawk sends the public part to Snowflake, and you download the private part as a file for your tool to use. A **passphrase** protects that private file, like a password protecting a document. Your tool uses the file and passphrase together instead of your current password.

## What are the impacts?

From **January 31, 2027**, tools and dashboards still using a **Password** to connect to your DataHawk Snowflake account will no longer connect or refresh. Update them before this date. Your data and access permissions stay the same.

## Get your private key and passphrase

If your team already generated a key pair for this connection, use its private key and passphrase. Otherwise, follow these steps. If you see **Access Forbidden**, ask a workspace Admin for help.

<Steps>

<Step>
### Open the existing Snowflake credentials

In DataHawk, open **Setup > Destinations > Snowflake > See Credentials** and select the connection your tool uses. [Open Snowflake credentials](https://analytics.datahawk.co/app/destinations/snowflake-ecosystem).
</Step>

<Step>
### Generate the key pair

Under **Public Key**, click **Generate keypair 1**.

  width={1431}

/>

Choose and confirm a passphrase of at least eight characters, then click **Generate and download**.

<img
  src="/images/help-center/connect-tools/snowflake/keypair-passphrase.png"
  alt="Generate Snowflake keypair dialog with passphrase and confirmation fields"
  width={561}
  height={308}
  className="rounded-lg border"
/>

Store the downloaded `.p8` file and its passphrase securely. DataHawk makes the private key available for download only when you generate it.
</Step>

</Steps>

<Callout type="warn">
If a key already exists, check with your team before regenerating it. Replacing it stops connections that use the previous private key from working once the new key is active.
</Callout>

## Change the credentials in your tool

When you generate a key pair, DataHawk registers the public key with Snowflake. In each tool that still signs in with a Snowflake password, update the saved credentials for the existing connection. Use the same Snowflake username, server, warehouse, database, and role.

Choose your tool below. If you use both Power BI Desktop and the Power BI service, update the credentials in both places.

<Tabs items={['Power BI Desktop', 'Power BI Service', 'Excel']}>

<Tab value="Power BI Desktop">

<Steps>

<Step>
### Edit the saved Snowflake credentials

Open your existing `.pbix` file. Go to **File > Options and settings > Data source settings**. Under **Global permissions**, select the Snowflake source used by the report, choose **Edit Permissions**, then select **Edit** under **Credentials**. [Microsoft's guide to editing credentials](https://learn.microsoft.com/en-us/power-query/connector-authentication).
</Step>

<Step>
### Switch to KeyPair

Choose **KeyPair**. Enter the existing Snowflake username, select the downloaded `.p8` file, and enter the passphrase you chose in DataHawk. Save the credentials, then use **Home > Refresh** to verify that the report can still query Snowflake.
</Step>

</Steps>

</Tab>

<Tab value="Power BI Service">

<Steps>

<Step>
### Open the published semantic model's credentials

In your Power BI workspace, open the **More options** menu next to the **semantic model** and select **Settings > Data source credentials > Edit credentials** for Snowflake. If the model uses a shared or gateway connection, ask the connection owner to update the existing Snowflake connection under **Settings > Manage connections and gateways**. [Microsoft's guide to Snowflake in the Power BI service](https://learn.microsoft.com/en-us/power-bi/connect-data/service-connect-snowflake).
</Step>

<Step>
### Sign in with the key pair

Set **Authentication method** to **KeyPair**. Enter the existing Snowflake username and the key's passphrase, select the downloaded `.p8` file under **Private key**, and click **Sign in**.

<img
  src="/images/help-center/connect-tools/powerbi/powerbi-7-renewed.png"
  alt="Power BI Service's KeyPair credentials dialog with user name, passphrase, and private key fields"
  width={511}
  height={893}
  className="rounded-lg border"
/>

Run **Refresh now** for an import model and check the refresh history. For DirectQuery, open the report and refresh its visuals to verify the connection.
</Step>

</Steps>

</Tab>

<Tab value="Excel">

<Steps>

<Step>
### Edit the existing Snowflake ODBC data source

On Windows, open **ODBC Data Source Administrator** and select **Configure** for the Snowflake data source your workbook uses under **User DSN** or **System DSN**. On macOS, edit the existing entry in iODBC Administrator or in your ODBC configuration file, such as `~/Library/ODBC/odbc.ini`. Keep the data source name (DSN) so the workbook continues to use it.

Set **Authenticator** to `SNOWFLAKE_JWT` and **Private Key File** (`PRIV_KEY_FILE`) to the full path of the downloaded `.p8` file. Supply the passphrase as `PRIV_KEY_FILE_PWD` through your organization's ODBC credential configuration. If your organization allows storing it in the DSN, use the private key passphrase field or its equivalent in the ODBC configuration file. Snowflake recommends against saving it in a Windows DSN because the registry stores it in plain text. [Snowflake's ODBC key-pair settings](https://docs.snowflake.com/en/developer-guide/odbc/odbc-parameters#using-key-pair-authentication).
</Step>

<Step>
### Clear the saved password and refresh

In the existing Excel workbook, open **Data > Get Data > Data Source Settings**. Under **Global permissions**, select the ODBC source and choose **Clear Permissions** for that source. Close the dialog and choose **Data > Refresh All**. If prompted, choose **Default or Custom** so the ODBC driver handles authentication, then verify that the workbook refreshes. [Microsoft's ODBC connector guide](https://learn.microsoft.com/en-us/power-query/connectors/odbc#connect-from-power-query-desktop).
</Step>

</Steps>

</Tab>

</Tabs>

For other tools, open the settings for the existing Snowflake connection. Change the sign-in method to **key-pair authentication**, select the `.p8` file you downloaded from DataHawk, and enter the passphrase you chose when you generated it.

After saving the credentials, open the report or workbook and refresh its data. If it refreshes on a schedule, check that the next scheduled refresh succeeds too. If the new key fails immediately after you generate it, wait a short while and try again. Snowflake may still be applying the public key.

## If the private key or passphrase is lost

Coordinate with your team before generating a replacement, then update your connected tools with the new file and passphrase. The original download cannot be recovered through DataHawk.

## Problems?

If you have connectivity issues or need assistance, feel free to contact support. Do not send your private key or passphrase.
